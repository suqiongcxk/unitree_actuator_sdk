# 低速四足策略重新训练与部署验收规范

## 1. 当前模型处置

- `model_700.pt`及对应ONNX禁止用于真机非零速度控制。
- 可保留用于零命令蹲伏复现、observation/ONNX数值对拍和离线安全测试。
- 不得通过放宽真机`JUMP`、目标变化率或反馈速度阈值绕过问题。

## 2. 训练前必须完成的只读审计

在修改reward或重新训练前，训练端应逐项给出文件、行号和实测证据：

1. 关节顺序是否严格为
   `[FL/FR/RL/RR hip, FL/FR/RL/RR thigh, FL/FR/RL/RR calf]`。
2. 四条腿的默认角度、action scale、关节方向、限位、执行器参数和减速比是否成对对称。
3. FL的碰撞体、足端link、接触传感器、关节驱动和初始状态是否与FR/RL/RR一致。
4. command采样范围、零命令比例、低速命令持续时间及curriculum是否让策略充分经历`vx=0.05~0.20 m/s`。
5. observation拼接和上一帧raw action语义是否与部署端48维接口完全一致。
6. 检查所有按腿索引的reward、termination、reset、contact和gait phase代码，重点排除FL漏索引、错索引或符号错误。

若发现FL资产、索引或reward不对称，应先修复根因并做最小复现实验，不能用提高总reward权重掩盖。

## 3. 第一版重新训练目标

- 第一阶段只覆盖平地单轴前进`vx=0.05~0.20 m/s`和零命令，不急于加入侧移、偏航或复杂地形。
- 明确定义命令语义：零命令稳定站立；`vx>=0.05 m/s`时四腿均应形成可重复的周期步态，不允许长期固定某一条腿。
- 保留速度跟踪目标，同时约束四腿步态完整性、左右/前后对称性、足端拖地和滑移。
- 增加action rate、目标关节速度、实际关节速度、关节加速度及力矩平滑约束，避免依赖高频大幅calf跳变获得速度。
- 训练和评估均保持50 Hz策略频率、`action_scale=0.25`及部署端相同的默认站姿、关节顺序和observation语义。

具体reward形式和权重必须结合训练源码审计后决定，并记录每次变更；不要一次同时修改大量reward而失去因果判断。

## 4. 仿真验收门槛

新checkpoint只有同时满足以下条件，才能导出候选ONNX：

- 至少10个独立seed，每个速度从fresh reset开始：零速5秒、斜坡进入命令、稳定10秒、回零3秒。
- 在`vx=0.05/0.10/0.15/0.20 m/s`下，FL/FR/RL/RR均有可靠、重复的周期离地，不允许任何腿在整段内固定。
- 无摔倒、base contact、NaN/Inf、非time-out reset或物理关节限位越界。
- 每帧最大`|delta q_des| <= 0.05 rad`，12关节`sum(|delta q_des|) <= 0.25 rad`，超过`0.03 rad`的关节数不多于3个。
- 最大实际关节速度先按commissioning门限`3.0 rad/s`验收；若训练端证明正常低速步态确有更高需求，必须提交分位数、峰值所在关节/相位及机构允许范围后再评审阈值。
- 回零过程连续，无突然切换默认站姿或集中目标跳变，最终恢复稳定四足支撑。

除最大值外必须同时报告均值、99%/99.9%分位数和超限连续帧数，避免少量高风险帧被平均值掩盖。

## 5. 导出与部署前对拍

1. 固定checkpoint、配置、seed和导出脚本，记录SHA-256。
2. 导出至少20帧连续真实rollout的48维observation、12维raw action和12维`q_des`。
3. 在部署端完成Python/C++ observation、ONNX raw action和`q_des`逐元素对拍。
4. 先运行离线日志回放，再运行`--dry-run --log`；两者均通过MotionSafety且无验证失败后，才允许进入吊带实机。
5. 首次实机仍只允许单轴、短脉冲、低幅值，并保留`Ctrl+C`、命令看门狗、反馈超时和12电机统一阻尼。

## 6. 每轮训练必须提交的结果

- checkpoint、ONNX、配置及其SHA-256；
- reward/asset/command/observation的实际diff；
- 训练曲线和上述多seed逐速度汇总CSV/JSON；
- 四足离地次数、首次离地时间、接触相位图；
- `q_des`变化、实际关节速度、关节范围、力矩和base状态统计；
- 明确的“通过/不通过部署门槛”结论，不只报告总reward或平均速度。
