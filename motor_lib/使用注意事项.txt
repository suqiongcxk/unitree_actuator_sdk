一、硬件接线
═══════════════════════════════════════════════════════════════════════════════

  1.1 RS-485 连接
  ──────────────
  电机侧 (GO-M8010-6)          Orange Pi 侧
  ─────────────────────        ─────────────
  RS-485 A  ─────────────────→  RS-485 模块 A
  RS-485 B  ─────────────────→  RS-485 模块 B
                                模块 DI ──→ 串口 TX (如 ttyS4)
                                模块 RO ──→ 串口 RX (如 ttyS4)
                                模块 DE+RE ──→ GPIO 方向控制

  1.2 RS-485 方向控制 (必须!)
  ─────────────────────────
  GPIO 控制 RS-485 芯片的 DE/RE 引脚:
  - GPIO 高电平 = TX 模式 (发送)
  - GPIO 低电平 = RX 模式 (接收)

  常用 RS-485 芯片: MAX485, SP3485, SN65HVD72 等。

  接线示例（单路总线）:
  ┌──────────────┐     ┌─────────────┐     ┌──────────────┐
  │ Orange Pi 5  │     │ RS-485 模块  │     │ GO-M8010-6   │
  │              │     │             │     │              │
  │ ttyS4 TX ────┼────→│ DI          │     │              │
  │ ttyS4 RX ────┼←────│ RO          │     │              │
  │ GPIO63  ─────┼────→│ DE + RE     │     │              │
  │              │     │ A ──────────┼────→│ RS-485+      │
  │              │     │ B ──────────┼────→│ RS-485-      │
  │ GND    ──────┼────→│ GND         │     │ GND          │
  └──────────────┘     └─────────────┘     └──────────────┘

  1.3 电机供电
  ──────────
  GO-M8010-6 供电电压: 24-48V DC
  务必使用独立电源，不要从开发板取电！
  多个电机并联到同一电源时注意总电流。

二、GPIO 引脚映射 (Orange Pi 5 Pro)
═══════════════════════════════════════════════════════════════════════════════

  2.1 GPIO 芯片布局
  ────────────────
  gpiochip0: GPIO0  - GPIO31   (物理引脚分散在 40pin 排针上)
  gpiochip1: GPIO32 - GPIO63
  gpiochip2: GPIO64 - GPIO95
  gpiochip3: GPIO96 - GPIO127
  gpiochip4: GPIO128 - GPIO159

  代码中的 GPIO 编号 = (gpiochip编号, 芯片内偏移)

  示例:
    物理 GPIO63 = gpiochip1 的第 31 号引脚
    → FastGPIO(1, 31)  或  FastGPIO(chip=1, line=31)

  2.2 如何确定 GPIO 映射
  ────────────────────
  方法 1: 查看 Orange Pi 5 Pro 引脚图
    https://orangepi.org → Orange Pi 5 Pro → GPIO Pinout

  方法 2: 在开发板上运行 (需要 root)
    sudo gpioinfo

  方法 3: 简单测试
    用一个 LED + 电阻串联到目标 GPIO 引脚和 GND，运行:
    echo 63 > /sys/class/gpio/export
    echo out > /sys/class/gpio/gpio63/direction
    echo 1 > /sys/class/gpio/gpio63/value   # LED 亮
    echo 0 > /sys/class/gpio/gpio63/value   # LED 灭
    echo 63 > /sys/class/gpio/unexport

  2.3 已知的可用 GPIO (Orange Pi 5 Pro 40pin 排针)
  ──────────────────────────────────────────────
  以下为常用空闲 GPIO，编号为 sysfs 全局编号:

    gpio63  (gpiochip1:31)  ← 示例代码中使用
    gpio120 (gpiochip3:24)
    gpio121 (gpiochip3:25)
    gpio122 (gpiochip3:26)
    gpio123 (gpiochip3:27)

  ⚠ 注意: 不要使用已经被系统占用的 GPIO (如 UART、SPI、I2C 功能引脚)

三、串口列表
═══════════════════════════════════════════════════════════════════════════════

  可用串口 (已验证):
    /dev/ttyS1  ~  /dev/ttyS7   共 7 路

  4 路总线方案推荐:
    总线 A: /dev/ttyS4  (GPIO 63)
    总线 B: /dev/ttyS5  (GPIO 120)
    总线 C: /dev/ttyS6  (GPIO 121)
    总线 D: /dev/ttyS7  (GPIO 122)

  ⚠ 确认串口未被其他服务占用:
    sudo lsof | grep ttyS

六、减速比说明
═══════════════════════════════════════════════════════════════════════════════

  库内部通过 queryGearRatio(MotorType::GO_M8010_6) 自动获取减速比 GR。

  转换关系 (GR = 转子转速 / 输出转速):
    指令 (输出端 → 转子端):
      q_rotor  = q_output  × GR      (位置)
      dq_rotor = dq_output × GR      (速度)
      tau_rotor = tau_output ÷ GR    (力矩被减速器放大)

    反馈 (转子端 → 输出端):
      q_output  = q_rotor  ÷ GR
      dq_output = dq_rotor ÷ GR
      tau_output = tau_rotor × GR

  ⚠ 力矩转换方向可以通过代码中的 TORQUE_IS_ROTOR 常量调整:
    motor_controller.cpp:202 和 parallel_bus.cpp 中的 getState()
    如果你的固件上报的是输出端力矩(N·m)，把该常量改为 false。

七、控制频率说明
═══════════════════════════════════════════════════════════════════════════════

  7.1 RS-485 单路总线频率上限
  ──────────────────────────
  每台电机单次收发周期 ≈ 300-500 µs (含 GPIO 翻转 + 17字节发送 + 16字节接收)

  1 路总线挂 N 台电机的实际频率:
    1 台电机: ~2000-3000 Hz
    3 台电机: ~600-1000 Hz
    6 台电机: ~300-500 Hz
    12 台电机: ~150-250 Hz

  7.2 多路并行方案
  ──────────────
  4 路总线 × 每路 3 台电机 = 12 台电机 同时达到 ~500 Hz

  ParallelBus 使用 clock_nanosleep(TIMER_ABSTIME) 做精确周期调度，
  不会因为循环执行时间波动导致频率漂移。

  7.3 选择合适的控制频率
  ────────────────────
  位置控制: 100-200 Hz 即可
  速度控制: 200-500 Hz
  力矩控制: 500-1000 Hz (需要尽量减少每路电机数量)

八、API 快速参考
═══════════════════════════════════════════════════════════════════════════════

  8.1 单电机 (MotorController) — 简单场景
  ─────────────────────────────────────
  MotorController motor(gpio全局编号, "串口路径", 电机ID);
  motor.setPosition(目标位置rad, kp刚度, kd阻尼);
  motor.setVelocity(目标速度rad/s, kd阻尼);
  motor.setTorque(目标力矩N·m);
  motor.brake();
  MotorState s = motor.getState();   // q, dq, tau均为输出端值

  8.2 单路多电机 (MotorBus) — 同一总线多个电机
  ──────────────────────────────────────────
  MotorBus bus(gpio全局编号, "串口路径");
  bus.addMotor(0);
  bus.addMotor(1);
  bus.setPosition(0, 0.5, 0.03, 0.01);
  bus.setVelocity(1, 3.14, 0.02);
  bus.sendRecv();    // 一次事务完成所有电机
  MotorState s0 = bus.getState(0);

  8.3 多路并行 (ParallelBus + MultiBusController) — 4路12电机
  ─────────────────────────────────────────────────────────
  MultiBusController controller;
  controller.addBus(gpiochip编号, 行偏移, "串口路径");   // 加多路
  // 为每路注册电机...
  controller.startAll(500);    // 全部启动 @ 500Hz
  controller.bus(0).setPosition(0, 0.5, 0.03, 0.01);
  controller.stopAll();

九、常见问题排查
═══════════════════════════════════════════════════════════════════════════════

  Q: 电机无响应?
  ──────────────
  1. 检查电机供电是否正常 (24-48V)
  2. 检查 RS-485 A/B 是否接反 (交换试试)
  3. 检查 GPIO 方向控制是否连接 DE+RE
  4. 检查串口路径是否正确 (ls /dev/ttyS*)
  5. 检查电机 ID 是否匹配 (出厂默认 ID=0)
  6. 用万用表测量 RS-485 A/B 之间应有 ~0.2-0.3V 的差分电压

  Q: getState() 返回的 q 是 0?
  ─────────────────────────
  1. data.correct 是否为 true? 若 false 说明 CRC 校验失败 → 检查接线
  2. data.merror 是否非零? 查看错误码含义

  Q: 频率达不到设定值?
  ──────────────────
  1. 每路电机太多 → 减少每路数量或增加总线
  2. sysfs GPIO 太慢 → 多路模式自动使用 FastGPIO (ioctl)
  3. 串口波特率不对 → 联系厂家确认 GO-M8010-6 波特率

  Q: 电机乱转或抖动?
  ────────────────
  1. kp/kd 值太小(无力)或太大(震荡)，从 0.01 开始慢慢加大
  2. 减速比方向反了？检查 queryGearRatio() 返回值
  3. 检查电源是否足够 → 多个电机同时运动时需要大电流
